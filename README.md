# knowledge-platform

Read-only индексатор Markdown + граф ссылок + MCP-сервер для vault Obsidian. Реализует этап 3 спецификации «Архитектура платформы знаний» (baseline v0.1, 2026-11-17). Vault не изменяется; индекс — производное состояние, пересобирается из файлов.

## Как это устроено

```
vault (~/KnowledgeBase, :ro) ─► индексатор (SQLite FTS5 + граф) ─► MCP по HTTP на tailnet-адресе
                                                                       │
                        propose_note ─► GitHub: ветка knowledge/<тема> ─► один PR на тему
```

- **Чтение.** `search` (BM25; смысловые векторы multilingual-e5-small по умолчанию ВЫКЛЮЧЕНЫ — `KNOWLEDGE_SEMANTIC=on` и образ с `KNOWLEDGE_SEMANTIC_BUILD=1` включают гибрид, слитый по рангам, ~800 МБ RAM; `mode=keyword|semantic`, `memory=all|agent|owner`, `parent=<хаб>` — только поддерево проекта; hostname/IP находятся целиком), `read` (заметка или секция), `related` (родители, дети, ссылки, обратные ссылки), `status`. Индекс обновляется раз в 5 минут внутри процесса.
- **Запись** идёт только через PR. `propose_note` создаёт новую заметку, `propose_edit` предлагает новое тело существующей (frontmatter сохраняется, `updated` обновляется). Все изменения одной темы (`topic`) попадают в одну ветку `knowledge/<slug>` и один PR: первый вызов открывает ветку и PR, следующие добавляют коммиты. Удалять заметки нельзя. Ревью — PR на GitHub.
- **Шаблон заметки** — как у тебя в Obsidian: `created`, `updated`, `aliases`, `parent`, `links`, `tags`, затем `# Название`. `parent` и `links` — имена заметок (в том числе ещё не существующих), `parent` может быть несколькими; `[[ ]]` оборачивает сервер. Заголовок добавляется, если его нет в теле. Полей `sources` нет.
- **Тег `agent-memory`** ставится автоматически только при создании заметки через `propose_note`: это память ИИ, а не заметка владельца. `propose_edit` теги не трогает и не добавляет, чужая (твоя) заметка остаётся твоей. В коммите правки указано, чья заметка: `(agent-memory)` или `(owner's note)`.
- **Поиск** смотрит все заметки. В каждом результате есть `tags` и `agent_memory`; параметр `memory` сужает выдачу: `agent`, `owner` или `all`.
- **Ветки не копятся.** Ветка без открытого PR (смержен или закрыт) удаляется фоновой очисткой — после двух проверок подряд, чтобы не удалить ветку, PR для которой ещё открывается.
- **Главное правило записи** закреплено в коде (`_guard`): писать можно только в ветки `knowledge/<тема>`; `master` и любые другие ветки сервер не трогает ни при создании, ни при правке, ни при очистке. Это защита на уровне кода, а не токена.
- **Ограничители:** не больше 5 открытых PR и 20 файлов в PR; тело с учётными данными отклоняется, а не маскируется; название без `/ \ : * ? " < > | # ^ [ ]`; имя, которое уже есть в индексе или в `master`, отклоняется.
- **Без токена** (`KNOWLEDGE_GITHUB_TOKEN` пуст) запись выключена, чтение работает.

## Запуск (контейнер)

```sh
docker compose up -d --build                                   # проверка на loopback
KNOWLEDGE_BIND=100.64.0.1 docker compose up -d                 # боевой: порт только на tailnet-адресе
sops exec-env secrets.sops.yaml 'KNOWLEDGE_BIND=100.64.0.1 docker compose up -d'   # с записью, токен из sops

claude mcp add -s user -t http knowledge http://100.64.0.1:7234/mcp   # подключить (любой узел tailnet)
```

Переменные: `KNOWLEDGE_BIND`, `KNOWLEDGE_PORT` (7234), `KNOWLEDGE_VAULT_PATH`, `KNOWLEDGE_INCLUDE` (по умолчанию `01 Архив`; список через запятую, пусто = весь vault), `KNOWLEDGE_GITHUB_REPO`, `KNOWLEDGE_GITHUB_TOKEN`. Лимиты и префикс веток — в `knowledge/server.py`.

## Токен и защита `master`

Fine-grained PAT на один репозиторий (vault): Contents и Pull requests — чтение/запись, больше ничего. Ограничить токен ветками `knowledge/*` нельзя, поэтому на `master` vault-репозитория нужен ruleset «изменения только через PR»: без него токен смог бы писать напрямую.

## Без контейнера

```sh
python3 -m knowledge sync --vault ~/KnowledgeBase --db ~/knowledge.db --include "01 Архив"
python3 -m knowledge search "hhh-sto-02" --db ~/knowledge.db
python3 -m unittest discover -s tests -t .
```

Замеры на реальном vault (717 заметок): полный прогон 1.4 с, повторный 0.07 с.

## Решения

- `note_id` = относительный путь. Переименование = удаление + добавление.
- Имя ветки (`knowledge/<slug>`) только ASCII: кириллица транслитерируется, остальное заменяется коротким хэшем, до 50 символов. С не-ASCII GitHub предупреждает о «скрытых символах».
- Коммиты из API без подписи (`unsigned`): после squash-merge через GitHub в `master` попадает коммит, подписанный самим GitHub.
- `.` и `-` — символы токена, поэтому `10.0.0.5` ищется целиком; завершающая точка предложения отделяется только в тексте для FTS.
- Поиск без стемминга: форма слова должна совпасть. Морфология — этап 4, если упрёмся.
- Аутентификации нет: доверие к tailnet, как у Timing. Реальное ограничение — ACL Headscale на порт 7234.
- По умолчанию индексируется только `01 Архив`: дневник и библиотека недоступны ни одному узлу tailnet. Книги не индексируются в любом случае.
- Запись идёт через GitHub REST без локального клона: два агента на одну тему не блокируют друг друга, гонка за создание ветки или PR разрешается повторным поиском.
- Контейнер: vault `:ro`, корневая ФС только для чтения, без capabilities, процесс не от root.

## Не сделано

Этапы 0–2 спецификации (бэкап, миграция памяти Claude), `propose_edit`, веб-интерфейс, перенос на `pve-local-l-02`, Qdrant/Neo4j. Фактическое состояние vault и блокеры — `docs/current-state.md`.

## Откат

`docker compose down -v` и удаление репозитория. Vault и GitHub-репозиторий vault не затронуты, кроме открытых PR и веток `knowledge/*`, которые закрываются вручную.
