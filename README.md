# knowledge-platform

Read-only индексатор Markdown + граф ссылок + MCP. Реализует этап 3 спецификации «Архитектура платформы знаний» (baseline v0.1, 2026-11-17). Vault не изменяется; индекс — производное состояние, пересобирается из файлов.

## Что есть

- `kp/index.py` — парсер (frontmatter, `[[links]]`, `parent`), чанки по заголовкам, SQLite FTS5 + граф, инкрементальный `sync`, удаления/переименования, маскирование строк с секретами, поиск циклов в `parent`.
- `kp/query.py` — `search` (BM25, точное совпадение hostname/IP), `read` (заметка/секция, не выходит за корень), `related` (parents/children/links/backlinks), `status`.
- `kp/server.py` — MCP (stdio), 4 read-only инструмента. Записи нет вообще.
- `tests/` — 10 тестов (инкремент, rename/delete, rebuild == incremental, секреты, traversal, граф).

## Запуск

```sh
python3 -m kp sync --vault ~/KnowledgeBase --db ~/kp.db        # инкрементально
python3 -m kp rebuild --vault ~/KnowledgeBase --db ~/kp.db     # с нуля
python3 -m kp search "hhh-sto-02" --db ~/kp.db
KP_DB=~/kp.db uv run --with 'mcp<2' python -m kp.server        # MCP
python3 -m unittest discover -s tests -t .                     # тесты
```

Замеры на реальном vault (717 заметок): полный прогон 1.4 с, повторный 0.07 с, 5447 чанков.

## Решения

- `note_id` = относительный путь. Переименование = удаление + добавление (стабильные id — позже, если понадобится).
- `.` и `-` — символы токена, поэтому `10.0.0.5` и `hhh-sto-02.example.dev` ищутся целиком; завершающая точка предложения отделяется только в тексте для FTS.
- Поиск без стемминга: русская морфология не покрыта (форма слова должна совпасть). Если это станет проблемой — этап 4 (эмбеддинги) решает именно это.
- `mcp<2`: в 2.x `FastMCP` переименован в `MCPServer`.
- Вместо выдуманного `score` — `rank` и сырой `bm25`.

## Блокеры (нужно слово владельца / доступ)

1. **Sync**: активен ли Remotely Save и в какой bucket; включён ли E2E-пароль (от этого зависит, читаем ли Markdown в S3). Одновременно стоят Remotely Save, Syncthing-метка и obsidian-git — какой из них источник для серверного зеркала? Рекомендация: зеркало = `git pull` из GitHub-репозитория vault (уже есть, версионирован, read-only для сервера через deploy key) или S3-reader, но не оба.
2. **Бэкап (этап 0)**: последний `vault backup` в git — 2026-09-20 (два месяца). Нужен тест восстановления до любых изменений.
3. **Хост**: где живёт зеркало + индекс (VPS с запасом диска или K8s); edge-VPS на 35 ГБ не подходит — вложений 3.9 ГБ.
4. **Приватность**: допустим ли plaintext vault (дневник, личное) на сервере; нужна ли сегментация (индексировать только `01 Архив/`?).
5. **Удалённый доступ к MCP**: способ аутентификации и домен (`knowledge.mcp…`, TLS 4-го уровня — отдельный сертификат).
6. **Память Claude (этап 2)**: порядок слияния с уже работающим контуром `knowledge` (harvest/mine) в `tools/claude/custom`.
